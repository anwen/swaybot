# tau3 战役总结：方法论沉淀（2026-10-22 ~ 10-28，v0.5.0）

一周内把 swaybot 的 tau3 成绩从"接近 0"推到全域测绘完毕，并留下两件比分数
更持久的东西：一套**失败驱动的改进环方法论**，和一组**杠杆边界的消融结论**。

## 方法论一：失败驱动的改进环（本次战役的主力引擎）

```
跑批 → 全量 transcript 落盘 → 逐题归因（golden × 实际调用 × KB 命中三方交叉）
→ 机制级修复（不泄题）→ 同题复测 → 提交
```

六轮循环的每次跃升都来自"读真实 transcript 找到的结构性缺陷"，而非先验猜测：
- 1214 循环：16 条消息被裁到 2 条 + 孤儿 tool 消息 → API 拒绝
- 协议文档被摘要器截掉工具签名（agent 连查 4 次同一文档）
- "说而不做"：give 交接只出现在叙述里，从不出现在调用里
- 上下文预算被三条 KB 结果击穿

**可复用原则**：改进假设必须由 transcript 证据触发；修复必须是机制级（可泛化
到未见任务）；每次修复必须同题复测归因。

## 方法论二：三杠杆消融（战役尾声的边界测绘）

| 杠杆 | 实验 | 结果 | 含义 |
|---|---|---|---|
| 知识注入 | 16 失败→30 规则→held-out 20 题 | 0/20 | 知识已被改进环蒸馏进静态指导；注入留给冷启动 |
| 步数预算 | 50→100，59 失败题 | 3/59 | 长链确实需要步数，但非主因 |
| 推理预算 | SWAYBOT_THINKING，20 题 | 0/20 | 推理在烧（耗时 2.1×）但不改结局 |

**结论**：glm-5.3 族的残余失败是工具编排的参数组装精度（DB 哈希零容忍）——
模型 agent 训练层能力，harness 侧三杠杆全部关闭，栈饱和。

附带发现：**单次评测噪声带 ±2-3 题**（用户模拟器路径分岔），n=1 结论必须
带这个误差棒；跨次 oracle 口径 0.196。
