## 命题

swaybot 的自我进化循环（失败 → 规则提取 → MemoryStore → 运行时注入 → 复测）
能否在**零积累新域**上自动运行并产生可测量的跨代增益？

这正是知识文件实验（REPORT.md 知识蒸馏节）确立的运行时注入的正确场景：
新领域冷启动、无静态指导可用。也是项目本命题（自我进化）的最小实证。

## 为什么 telecom

- 2285 题（最大的未开发域），我们零静态指导、零记忆——完美冷启动
- 任务 id 含 PERSONA 难度后缀（Easy/Hard/None），可按难度分层抽样
- 前置工作：先冒烟 1-2 题验证适配器兼容（telecom 无 retrieval_config，
  结构化任务 id 需逐个引号）

## 循环设计（全部复用现有组件）

```
for gen in 1..G:
    batch = 抽 N 个未测任务（难度分层）
    score[gen] = run(batch, guidance=(gen>0 ? memory 投影 : none))
    失败题 → LLMBrain 提取 ≤2 规则 → MemoryStore（佐证合并）
    memory 投影 → guidance 文件（下一代注入）
```

- G=4 代 × N=12：第 1 代无指导（基线），2-4 代携带前代规则
- **对照**：每代并行跑等量无指导任务（同难度分布）——增益必须归因于注入
  而非"同题重跑"或端点漂移
- Goodhart 防线：规则只进运行时注入文件（不动核心代码，无金样风险）；
  提取提示词禁止引用 task id；每代规则数量上限（≤24 条活规则，防膨胀）

## 判据

- 主：holding-out 分数随代数上升（gen4 > gen1，对照批平稳）
- 副：规则存活率（被后续代佐证/合并的比例）、注入成本（guidance 字符数）

## 风险

- telecom 适配器兼容性未知（冒烟先行）
- 若第 1 代基线即 0.5+， ceiling 不足——改用 Hard PERSONA 抽样
- glm-5.3-flash 的参数组装瓶颈在 telecom 同样存在：增益可能仍为 0——
  即使如此，"自动循环端到端跑通 + 增益测量方法"本身就是交付物（负结果
  已有 v10 同款先例）
