# tau3 知识迁移 A/B：架构验证首战（2026-10-23/24）

**问题**：swaybot 的记忆架构（MemoryStore + 行为注入）能否把学习相位积累的领域知识
转化为未见任务上的分数？

**设计**：banking_knowledge，bm25 检索变体（新 tau2 的 golden 需 srt 沙箱，缺席；
A/B 两臂同用 bm25，实验内同口径，与八月历史不可比）。学习集 task_001-005，
测试集 task_006/007/008/010/012（09/11/13 在新数据集中不存在）。
- 基线：测试集无知识 → **0.000**
- 学习：学习集 + 渐进注入（每题前 dump 记忆理论进 guidance；每题后从
  transcript+reward 提取 ≤2 条规则入 MemoryStore，佐证合并去重）→ 0.000
  （学习集本身在 bm25 下极难，教训全部从失败中提取）
- 迁移：同一测试集 + 完整学习文件注入 → **0.200**

## 结果

| 相位 | 分数 | 说明 |
|---|---|---|
| baseline | 0.000 | 5 题全败（bm25 检索难度） |
| learning | 0.000 | 规则从失败中学习（质量见下） |
| **transfer** | **0.200** | **task_006: 0→1**；其余 4 题仍败 |

**Δ = +0.200**（同题对照，temperature 0，固定顺序）。n=5，统计上薄弱
（一题翻转），但机制链路首次完整走通：失败 → 规则提取 → 记忆合并 → 注入 → 未见题得分。

## 学到的知识样例（注入生效的全文见 learned-guidance.md）

- 身份验证需 name + **两个**匹配数据点；新邮箱不能算"在档邮箱"；不足时主动升级而非循环
- 促销必须对照当前日期核验有效期（task_007 失败根因：推荐了已过期的 promo）
- 未经用户明确要求绝不自动提交申请
- 工具错误后要续接上下文恢复，不要重新问候

## 过程中架构自查出的 harness bug（元验证）

第一轮全零暴露：适配器的 k-clamp（e725998，为 KB_search_bm25 写）无条件
`k=20` 塞进 bm25 变体的 `KB_search()`（不接受 k）→ 9 连签名错误。**学习相位
的提取规则原样点名了这个 bug**——架构的学习回路诊断了自身宿主的缺陷。
已修复：仅当该工具 schema 接受 k 时 clamp，否则剥离（含 registry 回退）。

另：pkill 模式带路径导致旧进程幸存、双写结果文件——发现后清理重跑（第三次为干净数据）。

## 结论

1. 知识→能力转化**首次得到正信号**（+0.2），且注入的知识是可读的、可解释的领域规则
2. 学习集得分 0 说明：从失败学习有效，但**学习集自身的分数不是能力的量度**——
   真正的量度在迁移臂
3. 下一步放大信号：n=10/域、跨域复验（airline）、对照"错误知识"注入（负控）
